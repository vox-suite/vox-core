# Spaces Implementation Plan

> For agentic workers: use superpowers:subagent-driven-development or superpowers:executing-plans. Per user preference: no test files, no code comments.

**Goal:** Agent-built ideation graphs (Spaces) with a live canvas, chat steering, and an explicit Commit into a collection + planned spans.

**Spec:** `docs/superpowers/specs/2026-09-30-spaces-design.md`

**Stack:** Rust (vox-core: axum routes, worker jobs, rig + Gemini), Postgres, React Flow (`@xyflow/react`) in vox-desktop.

## Decisions taken to close the spec's open questions
- Client: vox-desktop first (Pulse already lives there).
- Effort limits: constants in `src/config.rs` (max steps, max children); surfaced as a "stopped: limit reached" node.
- Commit creates planned spans (`spans.status='planned'` already exists).
- Name stays "Spaces" (table prefix `space_`); rename is cheap later.

## Reality check vs spec
Agent tools today are compiled in and registered per agent via `.tool(...)` in `src/agents/conversation.rs` (~lines 219-355), not discovered at runtime. "All connected capabilities" therefore means: the Space agent gets the same toolset the general agent gets (web_search, search_places, get_route, spans, collections, etc.), built by one shared function. True runtime discovery is a later platform change, not part of this plan.

## Phase 1: Skeleton (no data access)
- Migration: `spaces` (id, user_id, title, intent, state `ideating|planned|committed|dropped`, agent_spec JSONB, committed_collection_id, timestamps); `space_nodes` (id, space_id, kind TEXT, title, body, data JSONB, state `running|done|stale|rejected`, position JSONB, derived_from UUID[], provenance JSONB, version); `space_edges` (space_id, from_node, to_node); extend `jobs_kind_check` with `run_space`.
- `JobKind::RunSpace` in `src/jobs/mod.rs`; worker dispatches it in `services/worker/runtime.rs`.
- Chat reuses `conversations`: `channel='space'`, `external_conversation_id=<space id>`, `agent_external_key='space'`.
- `space_architect.rs`: one-shot structured Gemini call (pattern of `schema_extractor.rs`) turning intent + `data_schemas` descriptions into `agent_spec` {mission, look_for, done_when, limits}.
- `space_graph.rs` tools (rig `Tool`, user-scoped like `tools/spans.rs`): `add_node`, `update_node`, `add_edge`, `remove_node`. Nodes are free-form (kind label chosen by the agent).
- `space_runtime.rs`: loop that runs the agent with the spec as system prompt and the graph tools; writes nodes as it goes.
- Routes in `spaces.rs`: create, list, get (graph + spec), send chat message (enqueues `run_space`), delete/drop. Streaming of node changes follows the pattern in `routes/live.rs`.
- Desktop: Spaces tab, React Flow canvas with live node updates, chat panel.

## Phase 2: Own-data access
- `data_query.rs`: `find_schemas(intent)` (embedding match on `data_schemas.embedding`) and `query_data(schema_ids, query_spec, range)` calling `src/application/chart_query.rs`. Agent proposes a `QuerySpec` (existing type in `src/domain/charts.rs`), never SQL.
- Shared toolset builder registers these plus the existing general-agent tools for Space runs.
- Nodes carry `provenance` (schema, query_spec, result summary); the desktop node renderer shows it.

## Phase 3: Research and fan-out
- Add `spawn_branch(title, brief)` tool: enqueues child `run_space` jobs, each scoped to a parent node; children write into their own branch.
- Enforce limits from config; write a limit node when hit.
- Agent prunes weak candidates with a stated reason and writes comparison and plan nodes.

## Phase 4: Steering
- Chat message on a Space: append to conversation, agent updates `agent_spec` and graph.
- Storage helper marks descendants of an edited/rejected node `stale` via `derived_from`; runtime re-runs only stale nodes.
- Side-effect tool calls create an `action_approvals` entry and a node awaiting approval.

## Phase 5: Conclude and commit
- Conclude: agent writes a decision node and the Space moves to `planned`.
- `POST /v1/me/spaces/:id/commit`: in one transaction, create the collection, planned spans (with `parent_id` hierarchy) from plan nodes, reminders for deadlines, set `committed_collection_id` and state `committed`. Reuses `src/storage/collections.rs` and `src/storage/spans.rs`.
- Desktop: Commit button on the decision node.

## Deferred
- Plan-vs-actual comparison, semantic search over spans, runtime capability discovery.

## Review focus
- User-scoping on every graph and data read (multi-tenant isolation).
- Commit atomicity; double-commit must be rejected.
- Runaway loops: limits must stop child spawning.
- Agent output that violates the node shape must not corrupt the graph.
- Concurrent chat during a running Space.
